# How the assessor's reply was applied

The developer supplied the assessor's five clarifications on 26 September 2026. They supersede interpretations in earlier development notes.

1. **Availability dates.** Node visibility uses `first_seen_year`, never `origin_year`. The existing edge rule additionally checks asserting-paper year and endpoint availability. Although 154 raw edges have unequal edge/article years, direct edge-year-plus-available-endpoints filtering and the existing conservative filter produce identical edge counts at all four chosen cutoffs: 374, 526, 983 and 1,429. No experiment snapshot needs replacing. Original metadata define some edge years as fact years; keeping the asserting-paper guard protects temporal honesty.
2. **Direction.** Member order is not a guaranteed source/target contract. The implementation treats memberships as sets for scoring and preserves the original sequence for traceability. It makes no directed coarsening claim. Earlier manual observations about first members are empirical observations only; they must not become schema guarantees. Directional inference is optional future work requiring relation semantics and explicit temporal/ambiguity rules.
3. **Required labels.** Assess levels 0 and 1. Existing deeper labels remain optional exports. The new faithfulness sample draws four groups per required level in each of four snapshots, rather than letting thousands of trivial singleton glosses dominate the score.
4. **Independent evaluation.** A documented blind LLM judge is acceptable; a domain expert is not required. New judges use fresh context, hidden configuration identities, no clustering embeddings or scores, recorded rubrics, and unchanged evaluation packets. Coherence includes matched type/size-preserving random groups. Faithfulness explicitly separates supported-but-vague text from unsupported assertions and reports an overclaim denominator. Human spot checks are recorded only when actually supplied; existing developer coherence review is not rebranded as new label review.
5. **All questions.** Frozen outputs for Q1–Q18 are evaluated. Q1–Q14 use method/claim criteria; Q15–Q18 use claim and evidence/source rubrics. Scores are separated by task type, with provenance-based source coverage and limitations. This is an evidence-retrieval evaluation, not a claim that an answer-generation agent was run. Existing flat and coarse-filter result lists stay fixed.

The protocol and anonymized inputs are in `evaluation_llm/`. Configuration identities are decoded only after the independent ratings have been written. This extends evaluation after assessor clarification; it does not retune clustering to improve benchmark answers.
